Skills Guide

Give your AI a specialty — reusable text files that turn a generalist into an expert
Cohort 2  |  March 2026
Student Resource
Every time you type instructions into Cursor or Claude Code, you are teaching your AI how to do a job. A skill makes those instructions permanent. Instead of retyping the same guidance every session, you save it as a text file and invoke it with a single command. This guide covers how skills work in both Cursor and Claude Code, how they differ from rules, and how to start building your own.
What Is a Skill?
Concept The Recipe Card Analogy
Think of a skill as a recipe card for your AI. A recipe card tells a cook exactly what ingredients to use, what steps to follow, and what the finished dish should look like. Without it, the cook can still make food — but the results will vary every time.
A skill does the same thing for your AI assistant. It is a plain text file that gives the AI a specific job, a point of view, and step-by-step instructions. Instead of explaining what you want every time you start a conversation, you hand the AI a recipe card and say “follow this.”
  • Without a skill: you retype the same instructions every session and hope the AI remembers your preferences
  • With a skill: you type one command, and the AI already knows the job, the format, and the standards
  • Skills are just text files — nothing proprietary, nothing complicated
  • They live in your project folder, so they travel with your code
Skills in Cursor
Setup How Cursor Skills Work
Location: Each skill lives in its own folder inside your project:
.cursor/skills/skill-name/SKILL.md
Format: Plain markdown with step-by-step instructions. Write it the same way you would explain a task to a colleague.
Global skills: Put them in ~/.cursor/skills/ to make them available across all your projects.
Source: cursor.com/help/customization/skills
Usage Creating and Invoking Skills
Create automatically: Type /create-skill in Cursor Chat. Cursor will walk you through it and generate the folder and file for you.
Create manually: Make the folder .cursor/skills/your-skill-name/ and add a SKILL.md file with your instructions.
Invoke: Type /skill-name in Cursor Chat to run the skill.
Attach as context: Use @skill-name to add the skill as background context without running it directly.
Skills vs Rules in Cursor
Cursor has two systems for guiding your AI: rules and skills. They serve different purposes. Rules are the house rules — always in effect, always enforced. Skills are recipes you pull out when you need them.
Feature Rules Skills
Location .cursor/rules/*.mdc .cursor/skills/name/SKILL.md
Format MDC (markdown with frontmatter) Plain markdown
Activation Automatic — always on, or triggered by file patterns On-demand — invoked with /name
Purpose Guidelines, conventions, coding standards Workflows, multi-step tasks, specialized jobs
Typical length Short — a few lines to a paragraph Longer — detailed steps, examples, expected output
Analogy House rules posted on the wall Recipe card pulled from a drawer
Rule of thumb: If the AI should follow it in every conversation, make it a rule. If you only need it for a specific task, make it a skill.
Skills in Claude Code
Setup How Claude Code Skills Work
Project skills: Save a markdown file in your project’s commands folder:
.claude/commands/skill-name.md
Global skills: Save to your home directory to use across all projects:
~/.claude/commands/skill-name.md
Format: Plain markdown. You can include a $ARGUMENTS placeholder anywhere in the file, and Claude Code will replace it with whatever text you type after the command.
Source: docs.anthropic.com/en/docs/claude-code/skills
Usage Invoking Claude Code Skills
Invoke: Type /skill-name in Claude Code. If your skill uses $ARGUMENTS, add your input after the command:
/review-code src/components/Header.tsx
Claude Code replaces $ARGUMENTS with src/components/Header.tsx and runs the skill.
Example skill file (.claude/commands/review-code.md):
Review the following file for accessibility issues, performance problems, and security concerns. File: $ARGUMENTS For each issue found, explain the problem and suggest a fix. Be specific and cite line numbers.
Example Skills

Here are practical skills you might create for your own projects. Each one turns a repetitive task into a single command.

Quality Code Reviewer
A skill that reviews code with a specific focus — accessibility, performance, or security. You define what matters most for your project.
  • Check for missing alt text, ARIA labels, keyboard navigation
  • Flag expensive re-renders or unnecessary API calls
  • Spot unvalidated user input or exposed secrets
Workflow Commit Message Writer
A skill that looks at your staged changes and writes a commit message following your team’s convention (Conventional Commits, a specific format, etc.).
  • Reads the git diff to understand what changed
  • Writes a concise summary that matches your style
  • Consistent messages across the whole team
Scaffolding Component Builder
A skill that generates new components matching your project’s patterns — file structure, naming conventions, default props, and test files.
  • Creates the component, styles, and test file together
  • Follows the same patterns as your existing code
  • Saves 10 minutes of boilerplate every time
Documentation Bug Report Generator
A skill that creates structured bug reports from a brief description — steps to reproduce, expected vs actual behavior, environment details.
  • Consistent format every time
  • Prompts you for the information that matters
  • Saves time for you and whoever fixes the bug
Skills and BMAD
Connection From Personal Skills to Professional Agents
If a skill is a recipe card, then BMAD agents are an entire cookbook written by a professional chef. Each BMAD agent is a specialist with deep domain expertise — a product manager, a tech lead, an architect — packaged as a skill that knows exactly how to do its job.
The commands you have already used — /bmad-brainstorming, /bmad-create-prd, /bmad-architect — are slash-command skills under the hood. They follow the exact same pattern: a text file with instructions that the AI follows when invoked.
  • Your skills: personal, written by you, focused on your specific workflow
  • BMAD skills: professional-grade, written by experts, battle-tested across many projects
  • The difference is scope and polish, not the underlying mechanism
  • Building your own skills helps you understand how BMAD works at a deeper level
Key insight: When you create your own skills, you are doing exactly what the BMAD framework does — giving an AI a specialty. The skills you build now are the foundation for understanding (and eventually customizing) professional agent workflows.
Tips
  1. Start simple — one skill, one job. A skill that does one thing well is more useful than one that tries to handle everything. Your first skill should take less than five minutes to write.
  2. Name skills by what they do, not what they are. review-accessibility is better than my-checker. write-commit is better than git-helper. Clear names mean you (and your teammates) can find the right skill without reading every file.
  3. Skills are just text files — version control them. Commit your skills alongside your code. They are part of your project, not separate from it. This also means anyone who clones your repo gets your skills automatically.
  4. Share skills with your team. If you write a skill that works well, commit it. Your teammates can use it, improve it, and build on it. Skills get better when more people use and refine them.
  5. Iterate based on results. If a skill produces output that needs the same corrections every time, update the skill. Treat it like code — refactor when it’s not working. The best skills evolve over a few rounds of use.
