Student Resource
Claude Code is Anthropic’s terminal-based AI tool. You describe what you want, it reads your project, writes code, and tests its own work. No visual editor — just text in, text out. Built for delegation (hand it a task, come back to results) and extensibility (hooks, plugins, skills, MCP, agent teams). Many developers use both Cursor and Claude Code.
Getting Started
Install
Claude Code requires a Claude Pro or Max subscription. Install via terminal:
curl -fsSL https://claude.ai/install.sh | bash
Verify: claude --version
If curl isn’t available: npm install -g @anthropic-ai/claude-code
Note: You already have this from pre-flight setup.
Launch
Open your terminal, navigate to your project folder, and type claude. That’s it. Claude Code reads your project files and is ready to work.
Type /help to see available commands.
Cursor vs Claude Code — When to Use Which
Cursor Visual Editor + AI
  • Familiar IDE: file explorer, tabs, preview panels, inline suggestions
  • Agent mode and background agents can work autonomously across files
  • Great for learning: you can see what’s happening visually
  • Choose from many AI models (Claude, GPT, Gemini) plus Cursor’s own models
  • Plan mode for interviewing you before building
Claude Code Terminal + AI
  • Text-based terminal: describe what you want, AI handles files, commands, and testing
  • Built for delegation: the AI reads, writes, runs, and iterates autonomously
  • Worktrees for isolated experiments, agent teams for parallel work
  • Deep integration with BMAD, Skills, and Anthropic’s ecosystem
  • Works from anywhere: terminal, mobile app, CI/CD pipelines
Tradeoffs.
Cursor — an IDE company building for software engineers. Multi-model (Claude, GPT, Gemini, their own). But you’re tied to their editor and ecosystem — if Cursor pivots or prices change, your workflows don’t transfer.
Claude Code — one product inside Anthropic, a much bigger AI company. Deep integration with Claude but locked to one model provider. Anthropic’s priorities are broader than dev tools — Claude Code may not always be the focus.
They’re converging from different directions. You don’t have to choose — many developers use both.
Key Concepts
Concept CLAUDE.md
Your project’s memory. Claude Code reads this file when it starts. Put project conventions, architecture decisions, and instructions here. Keep it lean — if it gets bloated, it becomes less effective.
Better alternatives for some things: AGENTS.md for agent-specific instructions, .claude/ folder for structured context.
Concept Skills
Packaged instructions for repeatable workflows. Like recipes the AI follows. You can create your own, install from marketplaces, or use ones that come with frameworks like BMAD.
Skills live in .claude/commands/ (Claude Code) or .cursor/commands/ (Cursor). Format: markdown files with specific structure.
Concept Plugins
Installable extensions that give Claude Code new capabilities. Browse the official plugin directory at claude.com/plugins or install community plugins from GitHub.
Recommended: Frontend Design — generates distinctive, production-grade UI instead of generic AI-looking interfaces. Handles typography, motion, layout composition, and visual depth.
Concept Worktrees
Isolated copies of your project on separate branches. Start an experiment without affecting your main code. If it works, merge it in. If it doesn’t, throw it away. Claude Code can create and manage these for you.
Concept Cloud Instances
Claude Code runs in the cloud, not just your terminal. Start a session from the web at claude.ai/code, continue it from your phone, or pick it back up in your terminal. Your work follows you across devices.
Concept Context Window
Claude Code has a limit on how much it can “see” at once. Long conversations degrade quality (context rot). Start fresh chats for new tasks. Use /compact to summarize and free up space.
Permission Modes
Claude Code asks for permission before making changes. You can control how much it asks. Cycle through modes with Shift+Tab before sending a message:
Mode CLI Flag What It Does
Default default Asks before file writes and most commands. Where everyone starts
Accept Edits acceptEdits Auto-approves file changes but still asks before running commands
Plan plan Claude describes what it would do without actually doing it. Good for reviewing strategy before committing
Auto auto Claude handles permissions on its own using an AI safety classifier. Two defensive layers filter out risky operations while allowing routine work to flow. Requires Team, Enterprise, or API plan
Bypass bypassPermissions Skips all permission checks. Only use in isolated environments (containers, VMs) where Claude can’t cause real damage
Auto mode is powerful but not magic. It blocks destructive commands (like rm -rf or force pushes) automatically. It works well for focused development sessions where you trust the task. Start with Default mode and work your way up as you get comfortable.
Claude Models
Claude Code can use different models. Switch with /model during a session. Each has different strengths:
Model Best For Speed Thinking Effort
Opus 4.6 Complex architecture, multi-file changes, difficult debugging Slowest, most capable Low, Medium, High, Max
Sonnet 4.6 Most tasks. Good balance of speed and quality Fast, very capable Low, Medium (recommended), High
Haiku 4.5 Quick questions, simple edits, mechanical tasks Fastest, most affordable No extended thinking
Thinking effort controls how much reasoning the model does before responding. Higher effort = better results on hard problems, but slower and more tokens. For most work, Sonnet 4.6 at medium effort is the sweet spot. Use Opus at high/max effort for architecture decisions or tricky bugs.
Essential Commands
Command What It Does
claude Start Claude Code in the current directory
/help See all available commands
/compact Summarize conversation to free up context
/clear Start a fresh conversation
/cost See how many tokens you’ve used
/model Switch between models (Opus, Sonnet, Haiku)
/memory View and edit Claude’s memory for this project
/permissions See what Claude Code is allowed to do
/doctor Check installation health and diagnose issues
claude --continue Resume your most recent session (if terminal crashed or you closed it)
Keyboard Shortcuts
Ctrl+C Stop Claude from running
Esc (single) Clears the text box. Careful: pressing it again stops Claude. If you accidentally stop it, type “continue all” to resume. Alternatives: Ctrl+U clears the whole line, Ctrl+W deletes the last word
Esc Esc (double-tap) Undo: restore code and conversation to a previous point. Better than Ctrl+C when you want to revert, not just stop
Ctrl+B Background the current task. Claude keeps working while you queue up your next message. When it finishes, it reads what you typed
Shift+Tab Cycle permission modes: Default → Accept Edits → Plan → Auto. Press before sending to change how much Claude asks for approval
Ctrl+G Open your system text editor for writing longer prompts (multi-paragraph)
Up arrow Recall previous prompts
CLI Flags (when launching)
claude -c Continue previous conversation
claude -p "prompt" Run a single prompt and exit (great for scripting)
cat file | claude -p "..." Pipe content into Claude Code for analysis
claude --add-dir ../other Include additional directories in context
Common Prompts

Getting Started:

Look at this project and tell me what it does, how it's structured, and what technologies it uses
Help me understand the code in [filename]. Explain it like I'm new to this

Building:

I want to add [feature]. Plan it out first, then implement it. Test it before telling me it's done
Fix the bug where [describe what's wrong]. Add error logging so we can see what's happening

Project Management:

Review my CLAUDE.md file. Is it clear and useful, or is it getting bloated? Suggest improvements
Create a skill that [describe what you want it to do] and save it to .claude/commands/
Conversation Flow
Claude Code’s input works differently from a chat app. Understanding the flow makes it much less confusing:
While Claude is Working You Can Type, Interrupt, or Background
  • Type ahead: start typing your next message while Claude is still responding. It queues up and Claude reads it when it finishes
  • Ctrl+B: background the current task. Claude keeps working while you write your next prompt. When it finishes, it picks up what you typed
  • /btw: ask a side question without interrupting or adding to the conversation history. Claude answers from what it already knows, then goes back to work
  • Esc (single): stops Claude mid-response so you can redirect before it finishes going the wrong way
Going Back Rewind: Undo for Your Whole Session
Press Esc Esc (double-tap) or type /rewind to open the rewind menu. You see every conversation turn with what changed. Pick one and choose:
  • Restore conversation only: roll back what Claude thinks happened, but keep file changes
  • Restore code only: undo file changes, but keep the conversation
  • Restore both: full rewind of conversation and code to that point
  • Summarize from here: keep everything but condense older messages to free up context
Limitation: Rewind can’t undo external actions like git push, npm publish, database changes, or API calls. Those happened in the real world.
Other Useful Inputs Quick Reference
  • ! command: run a bash command directly without Claude interpreting it. Output goes into conversation context
  • @filename: autocomplete file paths to reference specific files
  • Hold Space: push-to-talk voice dictation (if enabled)
  • Tab: accept prompt suggestions that appear based on your conversation
  • Ctrl+R: reverse search through your command history
  • /rename: name your session so you can find it later. Essential when running multiple sessions or using remote control from your phone
The Progression
Most people go through these stages as they get more comfortable:
  1. Single chat. One conversation, one task. You describe what you want, Claude builds it. This is where everyone starts
  2. Multi-chat. You learn to start fresh chats for new tasks. Managing multiple conversations and knowing when to start over becomes a skill itself
  3. Parallel agents + worktrees. You dispatch multiple Claude Code instances working simultaneously on different branches. Agent teams are being built into Claude Code (currently experimental, enable via CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS in settings). Community plugins like Superpowers also offer this. This is a key part of our curriculum
Don’t rush the progression. Start with single chat. Get comfortable. The multi-chat and parallel patterns will feel natural when you need them.
Good to Know
Pricing Max Plan Recommended
Claude Code works with Pro ($20/mo) but the Max plan ($100/mo) gives you significantly more usage for heavier work. For this course, Pro is fine to start. If you find yourself hitting limits during longer sessions, Max is worth it.
Context Tradeoff MCPs vs CLIs
MCP connections (like Supabase) are convenient because the AI calls them automatically. But they consume more of the context window, which can cause context rot faster. CLI tools (like gh for GitHub) are lighter on context but require explicit commands. Use MCPs when you need seamless integration, CLIs when context is tight.
Same model, different behavior. Claude behaves differently in different tools. Claude in Cursor, Claude at claude.ai, and Claude Code are the same model but the harness changes how it works. Each tool shapes the interaction differently.
Tips That Matter
  1. Start fresh for new tasks. Long conversations cause context rot. Each new task deserves a clean slate. Use /clear or just start a new session. Context rot means Claude’s responses get worse as the conversation gets longer.
  2. CLAUDE.md is your leverage. A good CLAUDE.md makes every conversation better. A bloated one makes them worse. Review it regularly. Think of it like a briefing document — concise and actionable beats long and exhaustive.
  3. Use worktrees for experiments. Don’t risk your working code. Create a worktree, try something wild, merge if it works. Worktrees are cheap. Failed experiments cost nothing when they’re isolated.
  4. Dispatch parallel agents for independent tasks. If you have tasks that don’t depend on each other, Claude Code can work on them simultaneously in separate worktrees. Agent teams are experimental but becoming core. BMAD workflows can run inside Claude Code agents, so you can have one agent doing brainstorming while another builds from an existing PRD.
  5. Check /cost regularly. Claude Code uses tokens. The Max plan gives you more, but it’s good to be aware of usage, especially during long sessions. Keeping an eye on cost helps you develop efficient prompting habits.
  6. Skills are your superpower. Once you find a workflow you repeat, turn it into a skill. Future you will thank you. Skills compound — each one you create makes your next project faster.
  7. Continue from your phone. Claude Code has a mobile app where you can monitor progress and continue conversations remotely. Great for checking on long-running tasks or making quick follow-ups when you’re away from your desk. Available on iOS and Android.
  8. Paste images from clipboard. You can paste screenshots directly into Claude Code. Great for showing UI bugs, design references, or error messages. Just copy an image and paste it into the prompt. Useful for “make it look like this” or “fix what you see in this screenshot.”
Claude Code + BMAD
Integration BMAD Workflows in the Terminal
BMAD installs slash commands into your .claude/commands/ folder. All BMAD workflows (/bmad-brainstorming, /bmad-create-prd, etc.) work directly in Claude Code. The terminal is BMAD’s natural home.
BMAD slash commands work inside Claude Code agent teams. Teammates can invoke commands like /bmad-create-story in parallel, each with independent context. One agent can brainstorm while another builds from an existing PRD. Agent teams are experimental (enable via CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS) but this integration is already working. We’ll explore this in the course.
Claude Code + MCP
Integration MCP Connections
MCP connections work in Claude Code just like in Cursor. Connect to Supabase, GitHub, context7, and other services. The difference: Claude Code can use these connections autonomously while working on tasks you’ve delegated, making them even more powerful.
