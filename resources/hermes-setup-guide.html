Hermes Setup Guide

From zero to "I can DM my agent" in ten minutes
Cohort 2  |  April 2026
Student Resource
Verified against Hermes v0.10.0
Hermes is a personal AI agent that lives on a $5 cloud server and talks to you through Telegram (or a terminal). It remembers you across sessions, writes its own skills as it learns from real use, and shows up first thing in the morning when you ask it to. This guide walks you through setting one up in about ten minutes — the same path we took for the yoga-bot reference deploy in Session 11.
Two ways to use this guide. Read it top-to-bottom and run each step yourself. Or skip to "Delegate to Claude Code" at the bottom and paste the starter prompt — the AI will drive, you'll approve at checkpoints.
Before You Start
Outcome What you'll have
  • A Hermes agent running as a systemd service on a $5 cloud VM.
  • You can DM it from Telegram.
  • It remembers what you tell it across sessions.
  • Voice memos transcribe automatically.
  • Need a scheduled task? Just ask it in chat.
Prep What you need
  • A $5/month Linux VPS. Linode, DigitalOcean, Hetzner all work well. Ubuntu 24.04 LTS is a good baseline Linux OS to use.
  • An SSH key on your laptop, added to the VPS at creation time. Run ssh-keygen -t ed25519 if you don't already have one.
  • One LLM API key. Anthropic (sk-ant-), OpenRouter (sk-or-), or Google AI Studio (AIzaSy…). Avoid new AQ.-prefix AI Studio keys — see the warning below.
  • A Telegram account (optional) if you want to DM the bot from your phone.
Heads up on Google AI Studio keys.
New AQ.-prefix keys return HTTP 400 "Multiple authentication credentials" against Hermes v0.10.0 — use OpenRouter instead. Older AIzaSy… keys still work fine. Known upstream bug, not a config error on your end.
The Five Steps
  1. SSH into your VPS On your laptop:
    ssh root@<your-vps-ip>
  2. Install Hermes On the VPS. This installs Hermes into ~/.hermes/, puts the hermes command on your PATH, and syncs about 80 bundled community skills. Takes 2-3 minutes.
    curl -fsSL https://raw.githubusercontent.com/NousResearch/hermes-agent/main/scripts/install.sh | bash source ~/.bashrc
    Verify:
    hermes --version hermes doctor
    doctor should be mostly green. Warnings about "provider auth not configured" are expected — you'll fix those next.
  3. Configure Pick Quick setup when prompted. The wizard asks about your inference provider (paste your API key), default model (accept the suggestion unless you have a reason not to), and messaging platform (say yes to Telegram if you want to DM the bot).
    hermes setup
    3a. The wizard opens with a Quick vs Full choice. Pick Quick — you can always run hermes setup again later to expand.
    Wizard intro — Quick vs Full setup.
    3b. Pick your inference provider. Use whichever matches the API key you have.
    Provider picker — 30+ supported providers. Anthropic, OpenRouter, and Google AI Studio are the easiest starting points.
    3c. The wizard asks if you want to wire up a messaging platform. Say yes if you want to DM the bot from your phone.
    "Connect a messaging platform?" — say yes for Telegram.
    3d. Hermes supports 18 messaging platforms. Telegram is the fastest path — no approval process, works globally, free.
    Messaging checklist — Telegram, Discord, Slack, Signal, WhatsApp, iMessage, and more.
    If you said yes to Telegram: on Telegram, search for @BotFather, send /newbot, pick a name and a username (ends in bot). BotFather gives you an HTTP API token — paste it into the wizard. Then search for @userinfobot on Telegram, send /start, and paste the numeric user ID it replies with into the wizard.
  4. Install as a system service So Hermes stays running across reboots and restarts itself if anything goes wrong:
    sudo hermes gateway install --system sudo systemctl start hermes-gateway sudo systemctl status hermes-gateway --no-pager
    The last line should show active (running).
  5. Test it If you wired Telegram: send your bot any message. It should reply within a few seconds.
    First round-trip with the yoga-bot reference deploy — /start, a "hi", the /sethome prompt, and a personalized reply.
    If you skipped Telegram: run hermes on the VPS — you're in a chat with your agent. Type something, press Enter. Type /help to see the slash commands. To make this chat the home for scheduled messages (cron results, cross-platform summaries), send /sethome to the bot on Telegram, or run /sethome in the CLI.
What To Do Next
Hermes is running. From here the useful moves are all inside the agent, not the shell.
An example USER.md seed — eight one-line fields. Hand-edit it, or let the agent capture it from your chat.
Seed Tell it about you
DM the bot something like this:
Hi, I'm Alex, I'm a [role], I work in [domain], I prefer [tone].
Its memory tool captures this into ~/.hermes/memories/USER.md. Every future session knows you.
Voice Edit SOUL.md
  • Open ~/.hermes/SOUL.md in a text editor.
  • Replace the default template with a short description of who you want the agent to be.
  • Changes take effect on the next message — no restart needed.
Schedule Just ask in chat
DM the bot:
Every weekday at 8am, check Hacker News for anything interesting and summarize three stories.
It wires up the cron itself. No systemd. No crontab -e.
Skills Browse what's installed
  • Type /skills in chat — lists what's already installed.
  • Type /skills browse — opens the Skills Hub to install more.
  • Skills live at ~/.hermes/skills/ — plain markdown, hand-editable.
Delegate Coding to Claude Code (Optional)
Optional Ride your Claude Pro/Max subscription
If you have a Claude Pro or Max subscription, install the claude CLI on the VPS and log in:
claude auth login --claudeai
Hermes routes heavy coding tasks through the bundled claude-code skill — using your subscription instead of API credits. Permitted under Anthropic's policy because the Claude Code CLI handles its own auth.
Practical payoff: your agent can do real coding work overnight — generate multi-week plans, refactor a project, write new skills — without racking up separate API bills.
Graduate to the Full Guide
This quickstart is deliberately minimal. You'll want the full production guide when any of these become real for you.
  • You want the VPS hardened. Firewall scoped to your IP, non-root service user, Docker terminal backend, auto-security-upgrades.
  • Your LLM provider rate-limits you. You want a fallback model wired in.
  • You want local inference. Ollama as fallback or primary.
  • You want to expose an HTTP endpoint from the VPS with a static-token auth gate.
  • You hit a documented bug. AQ-prefix Gemini keys, Ollama context-window trap, systemd crash loop, etc.
  • You want the cost envelope. Plan for migrating providers later.
What the full production deploy looks like when everything is in place — firewall, Docker backend, Claude CLI delegation, staged systemd unit. The quickstart above handles the "it runs" layer. The full guide adds the rest.
