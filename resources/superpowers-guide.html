Student Resource
Superpowers is the most popular Claude Code plugin (93,000+ GitHub stars). It makes the AI more disciplined: instead of just building whatever you ask for and hoping it works, Superpowers forces it to plan first, test as it goes, and verify before calling anything done. The result is higher quality code with fewer surprises. It uses more tokens and takes more time, but you spend less time fixing things later. Originally built for developers, but the concepts — plan before you build, test before you ship, verify before you celebrate — apply to anyone building software with AI.
Installation
Install Claude Code Plugin
/plugin install superpowers@claude-plugins-official
/reload-plugins
Update: /plugin update superpowers
Note: Also works with Cursor (/add-plugin superpowers) and Gemini CLI.
Core Philosophy
Principle 1 Test-Driven Development
Before building anything, write a test that checks if it works. This catches problems immediately instead of discovering them later when they’re harder to fix.
Principle 2 Systematic over Ad-Hoc
Follow a repeatable process instead of improvising. The AI can’t skip steps or cut corners, which means consistent results every time.
Principle 3 Complexity Reduction
Build only what you need right now. The AI tends to overbuild — Superpowers keeps it focused on the simplest solution that works.
Principle 4 Evidence over Claims
Don’t trust “done” — prove it. The AI must run the code and show you it works before moving on. No more “it should work” without evidence.
Note: Skills include explicit anti-rationalization patterns — 11 common excuses the AI might use to skip steps, with counters for each.
The 7-Phase Workflow
Brainstorm → Worktree → Plan → Implement → Test → Review → Finish
Phase 1 Brainstorming
superpowers:brainstorming
Before building anything, the AI talks through what you want. This catches misunderstandings before any code is written, which saves a lot of time.
  • Asks you questions one at a time to understand what you need
  • Proposes 2-3 approaches with trade-offs so you can pick
  • Writes a design spec that becomes the source of truth
  • Reviews its own spec for quality before moving on
  • Visual companion (v5.0+): can show mockups in a browser so you see what it's planning
Tradeoff: Superpowers uses a multiple-choice format for many questions, which makes it fast to respond but can mean you don't think as deeply about each answer. You can always type more if you want to go deeper. The more context you give, the better the output.
Phase 2 Git Worktrees
superpowers:using-git-worktrees
Creates a separate workspace so your experiments don't affect your main code. If something goes wrong, you can throw it away without losing your working version.
  • Sets up an isolated copy of your project on a new branch
  • Makes sure everything is working before you start changing things
  • Easy to discard if the experiment doesn't work out
Phase 3 Writing Plans
superpowers:writing-plans
Breaks the work into small, clear tasks (2-5 minutes each). Instead of one big "build the feature" instruction, you get a step-by-step checklist where each step does exactly one thing.
  • Each step has exact files, code, and commands so nothing is ambiguous
  • Reviews its own plan for quality before starting to build
Phase 4 Implementation
Two ways to build. Both follow your plan, but with different levels of quality control:
  • Option A (recommended): superpowers:subagent-driven-development. Launches a fresh AI for each task, so each one starts with clean context and focused instructions. Reviews each task twice before moving on. More thorough.
  • Option B: superpowers:executing-plans. Builds everything in one session with checkpoints where you approve before continuing. Simpler and faster, but less quality control.
Phase 5 Test-Driven Development
superpowers:test-driven-development
The core rule: write a test that checks if the feature works, then write the code to make it pass. This means you always know if something breaks. If the AI writes code before writing a test, it has to start over.
Why this matters: Without tests, you only find out something is broken when a user hits it. With tests, you find out immediately. Superpowers makes this non-negotiable.
Phase 6 Code Review
superpowers:requesting-code-review
The AI reviews its own work against the original plan. It flags issues by how serious they are. Critical issues have to be fixed before moving on. Think of it as a second pair of eyes that never gets tired.
Phase 7 Finishing
superpowers:finishing-a-development-branch
Makes sure everything works, then gives you four choices: merge into your main code, create a pull request for review, keep the branch for later, or discard it. Cleans up the workspace after.
Additional Skills
Skill When to Use
systematic-debugging Any bug or unexpected behavior. 4-phase root cause analysis
verification-before-completion Before claiming done. Must run verification and show output
dispatching-parallel-agents 2+ independent tasks without shared state
writing-skills Creating new skills. Applies TDD to documentation
How to Use It
You don’t need slash commands to trigger skills. Just describe what you want and the relevant skill activates naturally. Superpowers listens to your intent and engages the right workflow.
I want to add a dark mode toggle to the settings page
There’s a bug where the login form submits twice — help me debug it
Let’s plan out the notification system before we start building
Review the changes I made to the auth module
Practical Tips
Recommendations What Works Well
  1. Lean into brainstorming — the spec it produces is genuinely useful
  2. Spec and plan docs are the real artifacts — code is the byproduct
  3. Subagent development preserves context window in the main session
  4. Review the spec before moving to the plan — catch design issues early
  5. Use worktrees to keep your main branch clean while experimenting
Watch Out Gotchas
  1. Uses 5-10x more tokens than regular Claude Code. The thoroughness costs more
  2. Deliberately slower. More steps means more time, but fewer bugs to fix later
  3. Too much for simple tasks. Renaming a variable doesn't need a 7-phase process
  4. Verbose output. Expect detailed reasoning and long responses
  5. Long sessions cause drift. Start fresh when the quality starts dropping
  6. Monitor your usage. The subagent approach helps with context but uses more tokens overall
Superpowers vs Vanilla Claude Code
Aspect Vanilla Claude Code With Superpowers
Planning Optional, ad-hoc Mandatory specs and plans with review loops
Testing Suggested, often skipped Iron Law: failing test before any production code
Code Review Manual, when you remember Built-in review phase with severity levels
Branch Management Manual git commands Automated worktree creation and cleanup
Verification Trust the AI’s claim Must run verification and show output
Task Granularity Large, loosely defined 2–5 minute bite-sized steps
Context Management Single session, context degrades Subagents with curated context per task
Debugging Ad-hoc, pattern-matching Systematic 4-phase root cause analysis
Superpowers vs BMAD
Comparison: Superpowers is focused on Claude Code and enforces engineering discipline (TDD, code review). BMAD is a broader framework that works with many AI tools and focuses on the full product lifecycle (brainstorming through deployment). They solve different problems and can complement each other.
