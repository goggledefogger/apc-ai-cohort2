Superpowers is the most popular Claude Code plugin (93,000+ GitHub stars). Created by Jesse Vincent, it turns best practices — TDD, code review, planning, verification — from suggestions into mandatory gates. The tradeoff: more time and tokens for higher quality output and fewer bugs. Available in the official Anthropic marketplace and also works with Cursor and Gemini CLI.
Installation
Install Claude Code Plugin
/plugin install superpowers@claude-plugins-official
/reload-plugins
Update: /plugin update superpowers
Note: Also works with Cursor (/add-plugin superpowers) and Gemini CLI.
Core Philosophy
Principle 1 Test-Driven Development
Write tests first, always. No production code without a failing test.
Principle 2 Systematic over Ad-Hoc
Process-driven, not guesswork. Every skill enforces a procedure.
Principle 3 Complexity Reduction
YAGNI ruthlessly. Simplicity is the primary goal.
Principle 4 Evidence over Claims
Verify success before declaring completion. Skills are mandatory, not suggestions.
Note: Skills include explicit anti-rationalization patterns — 11 common excuses the AI might use to skip steps, with counters for each.
The 7-Phase Workflow
Brainstorm → Worktree → Plan → Implement → Test → Review → Finish
Phase 1 Brainstorming
superpowers:brainstorming
Triggers before any creative work. Hard gate: no code until design is approved.
  • Asks clarifying questions one at a time
  • Proposes 2–3 approaches with trade-offs
  • Writes spec to docs/superpowers/specs/
  • Runs automated spec review loop via subagent
Phase 2 Git Worktrees
superpowers:using-git-worktrees
Creates isolated workspace on a new branch.
  • Smart directory selection
  • Verifies worktree dir is gitignored
  • Runs project setup
  • Verifies clean test baseline
Phase 3 Writing Plans
superpowers:writing-plans
Breaks implementation into bite-sized tasks (2–5 minutes each). Each step is one action.
  • Plans include exact file paths, complete code, exact commands with expected output
  • Runs plan review loop via subagent
Phase 4 Implementation
Two options:
  • Option A (recommended): superpowers:subagent-driven-development — Fresh subagent per task with curated context. Two-stage review after each task. Never dispatch multiple implementation subagents in parallel.
  • Option B: superpowers:executing-plans — Same-session execution with human checkpoints. Simpler but less quality control.
Phase 5 Test-Driven Development
superpowers:test-driven-development
The “Iron Law”: no production code without a failing test. If code written before tests: delete it, start over.
Anti-rationalization: Includes 11 rationalization patterns with counters to prevent the AI from skipping test-first discipline.
Phase 6 Code Review
superpowers:requesting-code-review
Reviews against implementation plan. Issues by severity, critical issues block progress.
Receiving review: superpowers:receiving-code-review
Phase 7 Finishing
superpowers:finishing-a-development-branch
Verifies all tests pass. Exactly 4 options: merge locally, create PR, keep as-is, discard. Handles worktree cleanup.
Additional Skills
Skill When to Use
systematic-debugging Any bug or unexpected behavior. 4-phase root cause analysis
verification-before-completion Before claiming done. Must run verification and show output
dispatching-parallel-agents 2+ independent tasks without shared state
writing-skills Creating new skills. Applies TDD to documentation
How to Use It
You don’t need slash commands to trigger skills. Just describe what you want and the relevant skill activates naturally. Superpowers listens to your intent and engages the right workflow.
I want to add a dark mode toggle to the settings page
There’s a bug where the login form submits twice — help me debug it
Let’s plan out the notification system before we start building
Review the changes I made to the auth module
Practical Tips
Recommendations What Works Well
  1. Lean into brainstorming — the spec it produces is genuinely useful
  2. Spec and plan docs are the real artifacts — code is the byproduct
  3. Subagent development preserves context window in the main session
  4. Review the spec before moving to the plan — catch design issues early
  5. Use worktrees to keep your main branch clean while experimenting
Watch Out Gotchas
  1. 5–10x token consumption compared to vanilla Claude Code
  2. Slows things down by design — that’s the point, not a bug
  3. Overkill for simple tasks like renaming a variable or fixing a typo
  4. Verbose output — expect long responses with detailed reasoning
  5. Long sessions cause drift — start fresh when quality degrades
  6. Context window management — subagent mode helps but monitor usage
Superpowers vs Vanilla Claude Code
Aspect Vanilla Claude Code With Superpowers
Planning Optional, ad-hoc Mandatory specs and plans with review loops
Testing Suggested, often skipped Iron Law: failing test before any production code
Code Review Manual, when you remember Built-in review phase with severity levels
Branch Management Manual git commands Automated worktree creation and cleanup
Verification Trust the AI’s claim Must run verification and show output
Task Granularity Large, loosely defined 2–5 minute bite-sized steps
Context Management Single session, context degrades Subagents with curated context per task
Debugging Ad-hoc, pattern-matching Systematic 4-phase root cause analysis
Superpowers vs BMAD
Comparison: Superpowers is focused on Claude Code and enforces engineering discipline (TDD, code review). BMAD is a broader framework that works with many AI tools and focuses on the full product lifecycle (brainstorming through deployment). They solve different problems and can complement each other.
