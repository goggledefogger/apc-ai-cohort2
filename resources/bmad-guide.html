BMAD (Build More, Architect Dreams) is a framework that gives your AI tools a structured team of specialized roles. Instead of one AI doing everything, you work with domain experts that each think differently — the way a real product team does. This guide takes you from first setup to confident use.
Why BMAD?
Real Roles Not Made-Up Personas
BMAD’s agents map to actual roles at real companies: Product Manager, Architect, Developer, UX Designer, QA. These roles exist for a reason — each encapsulates a different way of thinking and a different craft. When you use BMAD, you’re simulating a team that thinks about your project from multiple angles.
Industry-Standard Outputs Documents That Outlast the Tool
BMAD produces PRDs (Product Requirement Documents), ADRs (Architecture Decision Records), sprint plans, and implementation specs. These formats existed before AI. Any developer, PM, or architect can read them. Your docs outlast the tool.
Well-Crafted Prompts Battle-Tested Through Real Use
Each agent is backed by community-iterated prompt engineering for each role. The BMAD community refined how each role thinks, what questions it asks, and what it produces. You could write your own prompts, but BMAD has done the work and tested it across many projects.
Portable Standard Markdown, No Lock-In
Everything BMAD produces is plain markdown. Your PRD works with or without BMAD, with or without AI, today and in five years. No proprietary formats, no vendor lock-in.
Note on terminology: BMAD calls its roles “agents” but they’re not autonomous AI agents. They’re specialized personas you invoke when you need a particular perspective.
Getting Started
Install 2 Minutes to Set Up
Prerequisites: Node.js 20+ and an AI tool (Cursor or Claude Code).
npx bmad-method install
  1. Where to install — current directory is fine
  2. Which AI tool — pick Cursor or Claude Code
  3. Which module — pick BMad Method (the software development one)
First Steps After Install
After install you get:
  • _bmad/ — the framework (don’t edit manually)
  • _bmad-output/ — where generated artifacts go
  • .cursor/commands/ or .claude/commands/ — slash commands for your AI tool
Verify it worked:
/bmad-help
It tells you what to do next. This is your starting point.
The Team — All 12 Domain Experts
Agent Role What They Do When to Use
Mary Analyst Brainstorms ideas, interviews you about needs, defines requirements Starting a new project or feature. When you need to think through what to build and why
John PM Scopes the project, writes the PRD, prioritizes features After brainstorming, to turn ideas into a structured plan with clear scope
Winston Architect Designs data structure, technical approach, makes technology decisions Before building, to plan how things connect and what the data looks like
Amelia Developer Writes code based on the plan, implements features When you’re ready to build. Give her the PRD and architecture docs
Sally UX Designer Designs user experience, interface layout, interaction patterns When functionality works and you want to make it intuitive and polished
Quinn QA Tests the app, finds bugs, writes test cases After building, to catch problems before users do
Bob Scrum Master Manages sprints, tracks progress, coordinates work For larger projects with multiple features to sequence
Barry Quick Flow Solo rapid development, streamlined workflow When you know what you want and just need to build fast. Skips the full team ceremony
Paige Tech Writer Generates documentation, user guides, API docs When you need to document what you built for others
bmad-master Orchestrator Coordinates between agents, manages handoffs When you’re not sure which agent to use, or when you need to coordinate a complex workflow
Brainstormer Ideation Creative brainstorming from multiple angles When you want to explore ideas before committing to a direction
Data Integrity Analyst Data QA Validates data models, checks for inconsistencies When your database schema needs review or you’re seeing data issues
For this course: you’ll mainly use Mary, John, Winston, Amelia, and Quinn. The others are there when you need them.
The Typical Flow
Mary (brainstorm) → John (scope & PRD) → Winston (architecture) → Amelia (build) → Quinn (test)
You don’t always need all of them. Start simple, add roles when you feel the need:
  • Quick project: Mary → Amelia (skip formal architecture)
  • Rapid solo: just Barry
  • Design-focused: add Sally after Amelia, before Quinn
  • Full process: Mary → John → Winston → Amelia → Quinn

Where Things Live
  • _bmad/ — The framework itself. Don’t edit manually. Updated via npx bmad-method install --action quick-update
  • _bmad-output/planning-artifacts/ — PRDs, architecture docs, brainstorming notes. Your project’s brain.
  • _bmad-output/implementation-artifacts/ — Sprint plans, code specs. Your project’s to-do list.
Tip: Check these files regularly. They’re your project’s memory. When you start a fresh chat, point the AI at these artifacts so it has context.
Tips That Matter
  1. Fresh chat for each workflow. Context rot is real. Long conversations degrade quality. Start a new chat for each major workflow step. When the AI gets confused, start over. Fresh chat = clean results.
  2. Plan before you code. Run Mary → John → Winston before Amelia. The planning docs create context that makes the code dramatically better. Skipping planning works for small things but falls apart for anything real.
  3. HALT means stop and think. BMAD workflows pause at HALT points for your input. Don’t rush past them. This is how you stay the conductor. HALT points prevent the AI from running off and building the wrong thing.
  4. You can skip roles. Not every project needs the full team. A quick feature might just need Amelia. A complex project needs the full flow. Match the process to the problem.
  5. Name your artifacts well. The AI reads file names. PRD.md is better than document1.md. architecture.md is better than plan.md.
  6. Barry for quick wins. When you know exactly what you want and don’t need planning ceremony, Barry is your friend. Solo rapid development without the team overhead.
  7. bmad-help is your compass. Lost? Don’t remember commands? /bmad-help inspects your project and tells you exactly what to do next.
What’s Next — Extensions
BMAD has extension modules for specialized use cases. We don’t cover these in the course, but they’re worth knowing about:
  • BMad Builder (BMB) — for building custom AI agents and tools
  • Test Architect Enterprise (TEA) — advanced testing frameworks
  • Game Dev Studio (BMGD) — game development workflows
  • Skills and plugins marketplace — community-contributed workflows
Note: These are separate npm packages. Install them alongside the core BMad Method module when you’re ready.
