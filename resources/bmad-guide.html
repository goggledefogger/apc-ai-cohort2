Student Resource
BMAD (Build More, Architect Dreams) is a framework that gives your AI tools a structured team of specialized roles. Instead of one AI doing everything, you work with domain experts that each think differently — the way a real product team does. This guide takes you from first setup to confident use.
Why BMAD?
Real Roles Not Made-Up Personas
BMAD’s agents map to actual roles at real companies: Product Manager, Architect, Developer, UX Designer, QA. These roles exist for a reason — each encapsulates a different way of thinking and a different craft. When you use BMAD, you’re simulating a team that thinks about your project from multiple angles.
Industry-Standard Outputs Documents That Outlast the Tool
BMAD produces PRDs (Product Requirement Documents), ADRs (Architecture Decision Records), sprint plans, and implementation specs. These formats existed before AI. Any developer, PM, or architect can read them. Your docs outlast the tool.
Well-Crafted Prompts Battle-Tested Through Real Use
Each agent is backed by community-iterated prompt engineering. BMAD doesn’t just fill in templates — the PM classifies your domain, looks up real concerns (privacy laws, accessibility, content moderation), and adapts them to your specific project. For example, it might note that edtech usually requires COPPA compliance but your project is for adults, so that doesn’t apply — but accessibility and data privacy still matter.
Portable Standard Markdown, No Lock-In
Everything BMAD produces is plain markdown. Your PRD works with or without BMAD, with or without AI, today and in five years. No proprietary formats, no vendor lock-in.
Note on terminology: BMAD calls its roles “agents” but they’re not autonomous AI agents. They’re specialized personas you invoke when you need a particular perspective.
Getting Started
Install 2 Minutes to Set Up
Prerequisites: Node.js 20+ and an AI tool (Cursor, Claude Code, Google Antigravity, ChatGPT Codex, or others).
Always use the terminal. Run this in your terminal, not Cursor Chat. The installer has interactive menus you need to see and select from. This is also good practice for the terminal, which is where you'll run Claude Code later.
npx bmad-method install
  1. Where to install: current directory is fine
  2. Which AI tools: scroll up/down and press Space to select all the ones you use (Cursor, Claude Code, etc.)
  3. Which modules: select the first three modules using Space. The first handles planning (PRDs, brainstorming). The second and third handle the actual building (AI-assisted development and the builder). You need all three for the full workflow
Why three modules? Module 1 (BMad Method) does planning: brainstorming, PRDs, architecture. Module 2 (Agent AI-Assisted Development) handles the implementation workflows. Module 3 (Builder) gives you the tools to actually build. Without all three, you can plan but not build.
Non-interactive install (if you know what you want):
npx bmad-method install --directory . --modules bmm,bmad,bmb --tools cursor,claude-code --yes
First Steps After Install
After install you get:
  • _bmad/ — the framework (don’t edit manually)
  • _bmad-output/ — where generated artifacts go
  • .cursor/commands/ or .claude/commands/ — slash commands for your AI tool
Verify it worked:
/bmad-help
It tells you what to do next. This is your starting point.
The Team — All 12 Domain Experts
How you actually interact: You load agents via slash commands like /bmad-agent-bmm-analyst. The agent shows a menu of options (trigger codes). You pick one and follow the workflow. You never type the agent's name — the BMAD docs give some agents names, but you never type those names. Just use the commands.
Role & Command What They Do When to Use
Analyst
/bmad-agent-bmm-analyst		 Brainstorms ideas, interviews you about needs, defines requirements Starting a new project or feature. When you need to think through what to build and why
PM
/bmad-agent-bmm-pm		 Scopes the project, writes the PRD, prioritizes features After brainstorming, to turn ideas into a structured plan with clear scope
Architect
/bmad-agent-bmm-architect		 Designs data structure, technical approach, makes technology decisions Before building, to plan how things connect and what the data looks like
Developer
/bmad-agent-bmm-dev		 Writes code based on the plan, implements features When you’re ready to build. Give it the PRD and architecture docs
UX Designer
/bmad-agent-bmm-ux		 Designs user experience, interface layout, interaction patterns When functionality works and you want to make it intuitive and polished
QA
/bmad-agent-bmm-qa		 Tests the app, finds bugs, writes test cases After building, to catch problems before users do
Scrum Master
/bmad-agent-bmm-scrum		 Manages sprints, tracks progress, coordinates work For larger projects with multiple features to sequence
Quick Flow
/bmad-agent-bmm-quickflow		 Solo rapid development, streamlined workflow When you know what you want and just need to build fast
Tech Writer
/bmad-agent-bmm-techwriter		 Generates documentation, user guides, API docs When you need to document what you built for others
Orchestrator
/bmad-master		 Coordinates between agents, manages handoffs When you’re not sure which agent to use next
Brainstormer
(accessed via Analyst → BP)		 Creative brainstorming from multiple angles When you want to explore ideas before committing
Data Integrity
(accessed via workflows)		 Validates data models, checks for inconsistencies When your database schema needs review
For this course: you’ll mainly use the Analyst, PM, Architect, Developer, and QA. The others are there when you need them.

Shortcuts: Quick project: Analyst → PM → Developer (skip architecture). Rapid solo: just /bmad-quick-dev. Full process: all four phases.
Navigating Between Steps
After completing a workflow, BMAD tells you where you are and what to do next. Here's what that looks like so you're not surprised:
Example After Creating Architecture
BMAD will show you something like this:
Phase 3 (Solutioning) — Progress: - Create Architecture (CA) — just completed - Create Epics and Stories (CE) — next required step - Check Implementation Readiness (IR) — required before implementation Optional steps you could do first: - /bmad-create-ux-design — UX Design (if your project has a user interface) - /bmad-validate-prd — verify the PRD is solid before building epics from it Recommended next: /bmad-create-epics-and-stories Each workflow should be run in a fresh context window for best results.
Key Concepts Required vs Optional Steps
  • Required steps must be done before moving to the next phase. BMAD won't let you skip them
  • Optional steps (like UX design or PRD validation) can make the output better but aren't blocking
  • Fresh context window means start a new chat for each workflow. This prevents context rot and gives each step clean, focused attention
  • /bmad-help always tells you where you are and what's next if you're unsure
Tip: Don't skip the optional steps on your first project. Things like UX design and PRD validation are where subtle issues get caught. On later projects you'll know which optional steps matter for your situation.
What Happens During Create PRD
The /bmad-create-prd workflow goes through several steps. It can feel long but they’re valuable steps. Here’s the bigger picture so you know where you are:
Step Name What It Does
1InitLoads the PRD template, validates prerequisites, reads existing project context
2DiscoveryAsks about the project: who is it for, what problem does it solve
2bVisionDefines the product vision and high-level goals
2cExecutive SummaryWrites a concise overview of the entire project
3Success CriteriaDefines what success looks like: measurable outcomes and acceptance criteria
4User JourneysMaps out how users will actually use the app, step by step
5DomainClassifies your domain (edtech, fintech, etc.) and surfaces relevant concerns like compliance, privacy, accessibility
6InnovationExplores innovative approaches and differentiators for your project
7Project TypeDetermines the project type and appropriate technical patterns
8ScopingDefines scope boundaries: what’s in v1, what’s deferred
9Functional RequirementsDetails the specific features and behaviors the app needs
10Non-Functional RequirementsPerformance, security, scalability, accessibility considerations
11PolishReviews and refines the full PRD for consistency and quality
12CompleteFinalizes the PRD, saves to _bmad-output, suggests next steps
Tip: You don’t have to agonize over each step. Answer what you can, say “your call” for things you’re unsure about, and you can always revise the PRD after. The first draft doesn’t have to be perfect.

Where Things Live
  • _bmad/ — The framework itself. Don’t edit manually. Updated via npx bmad-method install --action quick-update
  • _bmad-output/planning-artifacts/ — PRDs, architecture docs, brainstorming notes. Your project’s brain.
  • _bmad-output/implementation-artifacts/ — Sprint plans, code specs. Your project’s to-do list.
Tip: Check these files regularly. They’re your project’s memory. When you start a fresh chat, point the AI at these artifacts so it has context.
Tips That Matter
  1. Fresh chat for each workflow. Context rot is real. Long conversations degrade quality. Start a new chat for each major workflow step. When the AI gets confused, start over. Fresh chat = clean results.
  2. Plan before you code. Run Analyst → PM → Architect before the Developer. The planning docs create context that makes the code dramatically better. Skipping planning works for small things but falls apart for anything real.
  3. HALT means stop and think. BMAD workflows pause at HALT points for your input. Don’t rush past them. This is how you stay the conductor. HALT points prevent the AI from running off and building the wrong thing.
  4. You can skip roles. Not every project needs the full team. A quick feature might just need the Developer. A complex project needs the full flow. Match the process to the problem.
  5. Name your artifacts well. The AI reads file names. PRD.md is better than document1.md. architecture.md is better than plan.md.
  6. Quick Flow for quick wins. When you know exactly what you want and don’t need planning ceremony, Use /bmad-quick-dev. Solo rapid development without the team overhead.
  7. bmad-help is your compass. Lost? Don’t remember commands? /bmad-help inspects your project and tells you exactly what to do next.
  8. Initialize Git before installing. BMAD uses Git to track project state and changes. Run git init in your project folder before npx bmad-method install.
  9. Customize after install. Settings live in _bmad/_config/config.yaml. You can adjust your name, language, output preferences, and agent behavior after installation.
How BMAD Talks to You
BMAD agents use letter-based menus to present options. This can be confusing at first. Here’s what the common ones mean:
Brainstorming Modes When the Analyst asks you to pick
You’ll see something like:
Select: [A] Advanced Elicitation [P] Party Mode [C] Continue
[A] Advanced ElicitationThe Analyst interviews you with deeper, more structured questions. Good for thorough exploration
[P] Party ModeTwo agents brainstorm together, bouncing ideas off each other. Fun and often surprising
[C] ContinueLet the agent pick the approach and keep going. Good when you’re not sure which to choose
Tip: Try more brainstorming modes than you think you need. The different angles produce genuinely different insights. You can always run it again with a different mode.
General Pattern HALT Points and Letter Menus
Throughout BMAD workflows, agents pause and ask you to choose:
  • Letter codes like [A], [P], [C] — just type the letter
  • HALT means stop and wait for your input before proceeding
  • Trigger codes like BP (brainstorming), CP (create PRD) — type the code when the agent shows its menu
  • If you’re not sure what to pick, [C] Continue or just describing what you want in plain language usually works
What’s Next — Extensions
BMAD has extension modules for specialized use cases. We don’t cover these in the course, but they’re worth knowing about:
  • BMad Builder (BMB) — for building custom AI agents and tools
  • Test Architect Enterprise (TEA) — advanced testing frameworks
  • Game Dev Studio (BMGD) — game development workflows
  • Skills and plugins marketplace — community-contributed workflows
Note: These are separate npm packages. Install them alongside the core BMad Method module when you’re ready.
