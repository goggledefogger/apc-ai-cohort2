Student Resource
A quick reference for getting started with the BMAD Method. This covers what you need for the course — not everything BMAD can do, just the basics that work well. BMAD stands for Build More, Architect Dreams. It gives your AI tools (Cursor, Claude Code) a structured team of specialized agents. Instead of one AI that does everything, you work with agents that each have a specific role — just like a real team.
Why BMAD?
Real Roles Not Made-Up Personas
BMAD’s agents map to actual roles at real companies: Product Manager, Architect, Developer, UX Designer, QA. Each encapsulates a different way of thinking and a different craft. When you use BMAD, you’re simulating a team that thinks about your project from multiple angles.
Industry-Standard Outputs Documents That Outlast the Tool
BMAD produces PRDs (Product Requirement Documents), ADRs (Architecture Decision Records), sprint plans, and implementation specs. These formats existed before AI. Any developer, PM, or architect can read them. Even if you stop using BMAD, your documents are still useful.
Well-Crafted Prompts Battle-Tested Through Real Use
Each agent is backed by carefully iterated prompt engineering. The BMAD community refined how each role thinks, what questions it asks, and what it produces. You could write your own prompts, but BMAD has done the work and tested it across many projects.
Portable Standard Markdown, No Lock-In
Everything BMAD produces is plain markdown. Your PRD works with or without BMAD. It works with AI or without AI. It works today and it’ll work in five years. No proprietary formats, no vendor lock-in.
Note on terminology: BMAD calls its roles “agents,” but they’re not autonomous AI agents that go off and do things on their own. They’re specialized personas you invoke when you need a particular perspective. The word “agent” means different things in different contexts.

Installation
Install 2 Minutes to Set Up
Prerequisites: Node.js 20+ and an AI tool (Cursor, Claude Code, Google Antigravity, ChatGPT Codex, or others).
Always use the terminal. The installer has interactive menus. Good terminal practice before Claude Code.
npx bmad-method install
  1. Where to install: current directory is fine
  2. Which AI tools: Space to select yours (Cursor, Claude Code, etc.)
  3. Which modules: select the first three (planning + development + builder). You need all three for the full workflow
Non-interactive:
npx bmad-method install --directory . --modules bmm,bmad,bmb --tools cursor,claude-code --yes
What You Get After Install
  • _bmad/ — the framework (don’t edit manually)
  • _bmad-output/ — where generated plans and artifacts go
  • .claude/commands/ or .cursor/commands/ — slash commands for your AI tool
Verify it worked:
/bmad-help
Update later:
npx bmad-method install --action quick-update

Basic Workflows
The Core Path
This is the recommended flow for most projects. Start a new chat for each step.
/bmad-brainstorming → /bmad-create-prd → /bmad-create-architecture → /bmad-dev-story
Brainstorm your idea → turn it into a PRD → design the architecture → build features one story at a time. For bigger projects, add /bmad-create-epics-and-stories and /bmad-sprint-planning between architecture and dev.
The Shortcut (For Smaller Work)
/bmad-brainstorming → /bmad-create-prd → /bmad-quick-dev
The quick flow: /bmad-quick-dev asks clarifying questions, plans the approach, then builds it. One command that handles speccing and implementing without the full BMAD ceremony. Good for individual features, small apps, and iterative work.
Mary (brainstorm) → John (scope & PRD) → Winston (architecture) → Amelia (build) → Quinn (test)
The full team above shows every role. In practice, most projects use the core path (brainstorm → PRD → architecture → dev story). /bmad-help tells you what to do next at any point.
All Workflow Commands
/bmad-help Tells you what to do next based on project state
/bmad-brainstorming Brainstorm and explore your idea
/bmad-create-prd Create a product requirements document (required)
/bmad-create-architecture Design your app’s technical structure (required)
/bmad-create-epics-and-stories Break requirements into work items (required for big projects)

/bmad-quick-dev Clarify, plan, and build in one flow

Tips That Actually Matter
  1. Start a fresh chat for each workflow. Don’t reuse a chat from a previous workflow. The AI’s context gets muddled. This is context rot — long conversations degrade quality. When the AI gets confused, start over. Fresh chat = clean results.
  2. Plan before you code. Run Mary → John → Winston before asking Amelia to build. The plans create context that makes the code way better. Skipping planning works for small things but falls apart for anything real.
  3. Use /bmad-help when you’re lost. Don’t memorize commands. It tells you exactly what’s available and what to do next.
  4. Let the HALT points work. BMAD workflows pause for your input at HALT points. Don’t rush past them — they keep you in control. This is how you stay the conductor, not the apprentice.
  5. Your artifacts live in _bmad-output/. Everything BMAD generates goes there: planning-artifacts, implementation-artifacts, project-knowledge. Check these files — they’re your project’s memory.
  6. Barry is your friend for quick builds. Skip the full team ceremony when you know what you want. Designed for solo rapid development.
  7. Customize agents if needed. Add files to _bmad/_config/customizations/. But try the defaults first.
Common Gotchas
  • “Agent not found” — make sure you installed the BMad Method module, not just the core
  • AI can’t see _bmad files — restart your AI tool after install. It needs to re-index the project
  • Workflows feel slow — that’s by design. HALT points prevent the AI from running off and building the wrong thing (remember the Sorcerer’s Apprentice?)
  • Too many agents — you don’t need all of them. Start with Mary and Amelia. Add others as you need them
